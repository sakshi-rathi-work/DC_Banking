Part of [CLAUDE.md](../CLAUDE.md). Applies to all code, SQL, logs, tests, docs and UI. When in doubt: **boring, explicit, readable**.

## 1. General principles

- Correctness > clarity > brevity > cleverness.
- No dead code, no commented-out code, no TODOs without an issue note in the change log.
- No premature abstraction: extract only on the second real use.
- Every file has one responsibility; aim for < 300 lines per file.
- Comments explain **why** (protocol rule, invariant), not what. Reference doc sections where useful: `// architecture §8.1 step 3`.

## 2. TypeScript

- `strict: true`, `noUncheckedIndexedAccess: true`, `noImplicitOverride: true`. **No `any`** (use `unknown` + narrowing). `@ts-expect-error` needs a reason.
- ESM modules, Node 20. Prettier defaults + `singleQuote`, `printWidth: 100`, semicolons on.
- Naming: `camelCase` vars/functions, `PascalCase` types/classes, `SCREAMING_SNAKE_CASE` constants and env keys, `kebab-case.ts` file names (`berkeley.ts`, `election-manager.ts`). Tests: `*.test.ts` next to the file or in `tests/`.
- Prefer `type` aliases and discriminated unions for states (`type Role = 'LEADER' | 'BACKUP' | 'CANDIDATE' | 'NONE'`). Use exhaustive `switch` with a `never` check.
- Money: paise are held as `number` (always an integer, always below `Number.MAX_SAFE_INTEGER`, roughly ₹9×10¹³). Use a branded type `Paise = number & { __brand: 'paise' }` and a `toPaise()` helper that rejects non-integers, negatives where not allowed, and unsafe values. Convert Postgres `BIGINT` ↔ `number` once at the `pg` boundary (§4).
- Async: always `await` or explicitly handle promises; ESLint `no-floating-promises` is on. Use `Promise.allSettled` when one failure must not cancel siblings (e.g., sending heartbeats). Never use fixed `setTimeout` for correctness — only for protocol timeouts defined in architecture §1.2.
- Config: read env **once** in `config.ts`, validate with `zod`, export a frozen typed object. No `process.env` elsewhere.
- Time: never call `Date.now()` directly in business/algorithm code. Use the injected `Clock` (`clock.now()` = synced physical time; `clock.monotonic()` for durations). This keeps algorithms testable.

## 3. Module design (pure core + adapters)

Every distributed algorithm follows this shape so it can be unit-tested without a network:

```
election/bully.ts          // pure state machine: (state, event) → { state, actions[] }
election/election-manager.ts // adapter: timers + gRPC transport + persistence; executes actions
```

- **Pure core:** no I/O, no timers, no `Date`, no randomness (inject them). Input = events (`ELECTION_RECEIVED`, `OK_TIMEOUT`…), output = new state + list of side-effect *actions* (`SEND_ELECTION{to}`, `PERSIST_EPOCH`…).
- **Adapter:** wires transport (`PeerClient` interface), clock and storage; owns timers.
- Interfaces (`PeerClient`, `Clock`, `EventSink`, `Store`) live beside the core; real implementations in `grpc/`, `db/`; fakes in `tests/`.
- Same rule for: Berkeley (calculation = pure function `computeAdjustments(samples)`), Lamport (`LamportClock` class has no I/O), least-connections picker (`pickNode(nodes)`), replication applier ordering logic, idempotency hashing.

## 4. SQL & database

- Plain SQL files in `database/migrations/NNNN_description.sql`, forward-only, never edited after merge.
- `snake_case` tables (plural) and columns. PKs `id UUID` (generated by the leader in app code, **not** DB defaults — backups must receive identical ids). Timestamps `TIMESTAMPTZ`. Money `*_paise BIGINT`.
- Constraints belong in the schema: `CHECK`, `UNIQUE`, `NOT NULL`, FKs.
- Use parameterized queries only (`$1…`). **Never** interpolate values into SQL strings.
- Transactions go through `db/tx.ts` helper: `withTx(async (client) => …, { lockTimeoutMs })`. Business code never calls `BEGIN/COMMIT` by hand.
- Lock order is fixed (architecture §5.4). Any new write path must follow it and document deviations.
- Writes to **replicated tables** only occur inside leader write transactions (which append the log entry) or the backup applier. No ad-hoc writes.
- Convert `BIGINT` results with `pg` type parser to `number` (safe range) once at pool setup.

## 5. Logging & events

- `pino` JSON to stdout. Base fields on every line: `ts, level, node, service, event, requestId, lamport`.
- Add `txnId`, `peer`, `epoch`, `seq` when relevant. Level guide: `debug` heartbeats/timers; `info` normal state transitions; `warn` retries, timeouts, lag; `error` unexpected failures/invariant violations.
- `event` values come only from the vocabulary in architecture §13 (uppercase `SNAKE_CASE`). New events must be added there in the same change.
- A significant event is **both** logged and appended to `event_log` through `EventSink.emit({...})` — one call, no duplicate code paths.
- Never log secrets, passwords, JWTs, or full request bodies with credentials.
- Error logs include `err.code`, `err.message`, and stack only at `error` level.

## 6. API & proto conventions

- REST: plural nouns, `kebab-case` for multiword segments, verbs only for actions on collections that aren't CRUD (`/lab/clock/synchronize`). Query params `camelCase`. JSON `camelCase`. Success envelope `{ data, meta }`, errors `{ error, meta }` (api-reference §1).
- HTTP status: 201 on creation, 200 reads, 202 only for `COMMITTED_PENDING_REPLICATION`, 422 for business-rule failures, 4xx never retried by gateway.
- Proto: `package bank.v1`; messages `PascalCase`, fields `snake_case`, RPCs `PascalCase`, enums `UPPER_SNAKE` (use strings for lab-friendly readability only where noted). Never reuse or renumber field numbers; add new fields at the end.
- Validation: gateway `zod` schemas live in `routes/*.schema.ts`; node re-checks invariants (`amount > 0`, ownership) defensively.
- Idempotency key format: UUID v4 generated per **user submission** (frontend) — retries of that submission reuse it.

## 7. Errors

- Domain errors extend `AppError(code, message, { details, retryable })` where `code` is from api-reference §2. One mapper converts `AppError` ⇄ gRPC status (trailer `x-error-code`) ⇄ HTTP.
- Do not `catch` and ignore. Either handle with a defined behavior (retry, mark peer suspect, fall back) or rethrow with context (`cause`).
- Timeouts are errors, not log lines. Every RPC wrapper sets a deadline.
- User-facing messages are short, specific, and actionable ("Balance is lower than the requested amount."). No stack traces or SQL text in responses.

## 8. Testing conventions

- **Vitest.** Unit tests co-located (`foo.test.ts`); integration/distributed in `/tests/{integration,distributed}/`.
- Test names describe behavior: `it('rejects the second of two concurrent withdrawals when funds cover only one')`.
- Arrange–Act–Assert; one behavioral assertion focus per test.
- **No fixed sleeps.** Use `waitFor(predicate, { timeoutMs, intervalMs })` from `tests/helpers/wait.ts`. Algorithm timers use a fake clock in unit tests.
- Pure cores get table-driven tests (`it.each`).
- Distributed tests drive the real stack via `tests/helpers/cluster.ts` (`startCluster()`, `stopNode(id)`, `startNode(id)`, `api(token)`), use a separate compose project name, and clean up in `afterAll`.
- Tests must be independent: create unique users/accounts per test; never rely on seed data.
- Every bug fix adds a regression test.
- Test matrix and required scenarios: [testing-and-demo.md](testing-and-demo.md).

## 9. Git & docs

- Branch per phase: `phase-05-elections`. Commits follow Conventional Commits: `feat(election): implement ring token skipping`, `fix(replication): …`, `test(concurrency): …`, `docs(architecture): …`. Scopes: `gateway, node, bank, cluster, clock, election, replication, lb, db, proto, frontend, docker, tests, docs`.
- One logical change per commit; each commit builds and passes unit tests.
- `.env`, `node_modules`, `dist`, generated proto code are git-ignored.
- Docs updated in the same commit as the behavior change; add a row to CLAUDE.md §14 change log.
- Markdown: ATX headings, tables for contracts, fenced code blocks with language tags, relative links.

## 10. Frontend

### 10.1 Principles
- It must look like a **banking app first**, lab tool second. Calm, trustworthy, uncluttered.
- Every lab visualization renders **live backend data**. If data is unavailable, show an explicit empty/error state — never placeholder numbers.
- Demo/fixture data lives only in `src/__fixtures__/` for component tests.

### 10.2 Navigation (React Router)

```
/login  /register
/                      Dashboard
/accounts              Accounts list + create
/accounts/:id          Account detail + deposit / withdraw / transfer + history
/transactions          Full history with filters
/cluster               Cluster overview (nodes, leader, replication lag, load summary)
/lab/rpc               1 RPC Communication
/lab/concurrency       2 Multithreading / Concurrency
/lab/physical-clock    3 Physical Clock (Berkeley)
/lab/logical-clock     4 Logical Clock (Lamport)
/lab/bully             5 Bully Election
/lab/ring              6 Ring Election
/lab/replication       7 Replication & Consistency
/lab/load-balancing    8 Load Balancing
/lab/fault-tolerance   9 Fault Tolerance
```
Layout: left sidebar with two groups — **Banking** (Dashboard, Accounts, Transactions) and **Distributed System** (Cluster, then the 9 lab pages). Top bar: current user, **cluster status pill** (leader node + epoch; amber during election, red when no leader).

### 10.3 Lab page template (every lab page)
1. **Header:** title + one-sentence "What this demonstrates".
2. **Live state panel:** real data (nodes, values) refreshed by polling.
3. **Action panel:** buttons that call real lab endpoints (disabled with tooltip while an action is running).
4. **Event timeline:** filtered `/system/events` (relevant event types), ordered by `(lamport, node)`, with Lamport and node chips.
5. **"Expected result" note:** short text explaining what the evaluator should observe.

### 10.4 Design tokens (Tailwind)
- Font: Inter (system fallback). Base 14–16 px; numbers `tabular-nums`.
- Neutral palette `slate`; primary `indigo-600`; success `emerald-600`; warning `amber-500`; danger `rose-600`; info `sky-600`.
- Cards: `rounded-xl border border-slate-200 bg-white shadow-sm p-4`; page background `slate-50`. Support dark mode via `class` strategy only if time permits (not required).
- Spacing scale: 4/8/12/16/24/32 (Tailwind default); max content width `max-w-7xl`.
- **Node colors** (consistent everywhere): node 1 `sky-500`, node 2 `violet-500`, node 3 `amber-500`; gateway `slate-500`. Role badges: LEADER `emerald`, BACKUP `slate`, CANDIDATE `amber`, DOWN `rose`, DB_DOWN `rose` outlined, CRASH/PARTITION `fuchsia` outlined.
- Status dots + text label (never color alone).

### 10.5 Components (`src/components/`)
`NodeCard`, `RoleBadge`, `StatusPill`, `LamportChip`, `EventTimeline`, `MessageSequence` (election/RPC arrows between node lanes, SVG), `LagBar`, `ShareBar` (load distribution), `ClockTable`, `MoneyInput`, `Money`, `ConfirmButton` (for destructive lab actions), `EmptyState`, `ErrorState`, `Skeleton`. Charts: Recharts (line for lag/offsets over time, bar for load share).

### 10.6 Data fetching
- TanStack Query. `refetchInterval`: 1000 ms for cluster/nodes/elections/replication on active lab pages; 2000 ms elsewhere; paused when the tab is hidden.
- One typed API client (`src/api/client.ts`) using `fetch`; attaches JWT; surfaces `meta` (`requestId`, `servedBy`, `lamport`). Show `servedBy`/`processedBy` badges on banking responses — it makes the distribution tangible.
- Mutations: generate `Idempotency-Key` with `crypto.randomUUID()` **when the form is opened/submitted**, and reuse it on retry of the same submission; new key for a new submission.
- Token storage: in memory + `sessionStorage` (lab project; note XSS trade-off in README). Auto-logout on 401.
- Loading/empty/error states required on every data view.

### 10.7 Formatting rules
- Money: `Intl.NumberFormat('en-IN', { style: 'currency', currency: 'INR' })` from paise ÷ 100 (`₹1,25,000.50`). Never use floats for arithmetic — convert only for display.
- Timestamps: local time `DD MMM YYYY, HH:mm:ss`; lab pages show milliseconds and also UTC on hover.
- Lamport values: `L=142`; node refs: `Node 3`. Clock offsets: signed with unit (`+3011 ms`).
- Account numbers grouped `4029 1837 4655`.

### 10.8 Accessibility & UX
- Semantic HTML, labeled inputs, visible focus rings, `aria-live="polite"` for toasts and election status changes, minimum contrast AA.
- Destructive lab actions (crash, partition) use `ConfirmButton`.
- Disable submit while pending; show the resulting transaction reference and which node processed it.

### 10.9 Copy tone
Plain, precise, non-jargon in the banking area ("Transfer sent", "Not enough balance"); technical but concise in lab pages ("Node 2 sent ELECTION to Node 3 — no reply within 1500 ms").
